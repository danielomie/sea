_Time: wall-clock average. Memory: peak RSS. Lower is better. The JIT (off by default)
compiles hot functions and hot loops (incl. the top-level chunk, entered mid-loop via OSR)
in a background compile-server process, so the interpreter never waits for it. It speeds up
compute-bound code — integer/float arithmetic, numeric loops, calls, array and field access
(e.g. `loops`, `sort`, `matrix_mul`, `fib_recursive`). Programs shorter than one compile
(~30-50ms: `primes`, `fib_iterative`, `closures`, `string_ops`) finish before native
code is ready and run at interpreter speed; workloads dominated by the C runtime (`map_ops`)
gain little._
